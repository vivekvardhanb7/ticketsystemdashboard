Intake handling
Website form: preserve the original field values, message and uploaded media. Phone and machine/location remain optional. Email: use sender, subject, message and attachments; collect missing account, request and machine details during triage. WhatsApp: use sender phone, messages and media; collect name, email, account type and machine details when needed.
“Not collected” means a structured field has not been confirmed. “Other” remains an explicit choice from the website form.
Illustrative ticket data. Ticket navigation and status buttons are linked in the prototype; search and filters remain design states.
Status flow: Open → In Progress → Closed. In Progress offers Close ticket only. Reopen ticket is available only when Closed.
Reply routing: Website form → Email. Email → Email only. WhatsApp → WhatsApp only. Internal notes are never sent to the customer.
Language: English is active in this draft. German is planned as the default for launch; no German screens are enabled yet.
New Ticket prototype: select the name field to see a filled example, then Create ticket. Empty submission shows required-field errors. Cancel returns to the dashboard.
Email notifications: confirmation on creation; update on Start progress; agent reply when Send reply is used; closure on Close ticket; reopening only from Closed. Send emails only for Website form / Email tickets. WhatsApp tickets stay on WhatsApp.
